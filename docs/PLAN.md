# PaperTradeAgent 建议及规划书

> 定位：面向投资小白的 A 股**模拟交易 + 金融素养教育**多智能体系统（非实盘、非投资建议），
> 同时是一套可作为参考实现的**多智能体（Multi-Agent）应用开发示例**。
> 本文件基于当前前后端既有模块，整理可落地的优化与扩展建议。
> 更新日期：2026-08-16

---

## 一、定位再确认（为什么要做这份规划）

PaperTradeAgent 不是量化实盘系统，它的核心价值有两个维度：

1. **业务维度**：在券商级规则（T+1、涨跌停、价格笼子、佣金、印花税、中国交易日历）下，
   提供一个低风险、可重复练习的**模拟交易与投资者教育**环境，帮助投资小白建立纪律、练习操作、积累认知。
2. **工程维度**：用 LangGraph 编排 6 个 LLM Agent，完整落地了
   「意图识别 → 任务规划 → 多轮工具调用 → 质量门 → 有界反思 → 人机确认 → 可观测评估」的闭环，
   是一个**开箱即用、可拆解学习、可二次开发**的多智能体应用参考实现。

后续所有优化都应围绕这两个定位展开：**不追求实盘收益，不堆无效复杂度，每个能力都有真实接口与页面支撑。**

## 二、定时任务的利用与扩展

### 现状

- `services/scheduler.py` 提供 `interval` / `daily` 两类后台调度，15 秒轮询一次，执行时**复用 LangGraph 主链路**（`_execute_prompt`）。
- `api/scheduler.py` 暴露 CRUD 与「立即执行」。
- `scheduled_tasks` 表持久化任务，前端「设置 → 定时任务」支持新建 / 暂停 / 立即执行 / 删除。

### 建议

1. **Cron 表达式支持（P1）**
   在现有 `interval` / `daily` 基础上引入 `cron` 字段（如 `0 9 30 * 1-5`），用轻量解析器做匹配，
   覆盖「每周一至周五 9:30」「每月首个交易日」等更贴近真实交易节奏的触发时机。

2. **触发时机与交易日历联动（P1）**
   定时任务在「非交易日 / 非交易时段」触发时应自动顺延到下一交易日开盘，或标记为「跳过」并记录原因。
   复用 `trading_time.TradingTimeChecker`，避免在休市时反复执行无意义的分析。

3. **任务结果回写会话（P0，已具备基础）**
   当前定时任务执行结果仅落库 `scheduled_tasks`。建议把结果**推送到最近一次会话**并持久化，
   复用 `session_manager.push_system_message` + `db.save_message`（与持仓监控同款机制），
   让用户在聊天界面直接看到「定时复盘 / 定时盯盘」的产出，形成「任务 → 结果 → 对话」的闭环。

4. **任务模板与预设（P2）**
   内置常用模板：开盘前 9:25 竞价概览、午盘 11:30 持仓巡检、收盘 15:00 复盘报告。
   用户一键创建，降低配置门槛，契合「教育 + 示例」定位。

5. **任务级限流与幂等（P2）**
   为同一任务加 `last_run_at` 幂等锁，避免轮询窗口内的重复触发；执行失败指数退避，不阻塞调度循环。

## 三、持久化监控的进一步优化

### 现状

- `services/portfolio_monitor_bg.py` 在 FastAPI `lifespan` 中启动后台循环：
  交易时段每 60 秒、非交易时段每 300 秒巡检一次。
- 已落地「**分批买卖纪律**」：
  - 单只持仓亏损 ≤ -8% → 果断减仓离场（可分批卖出以控制冲击成本）。
  - 个股日内涨跌幅 > ±3% → 分批止盈 / 止损。
  - 组合总亏损 ≤ -5% → 触发风控红线，果断离场。
  - 组合回撤 ≤ -2% → 分批减仓预警。
- 建议通过 `_target_session()` 找到活跃或最近会话，`_emit()` 同时做 **SSE 实时推送 + 会话历史持久化**，
  前端经 `/api/session/stream` 接收，渲染为带「按此建议执行」按钮的风控卡片。
- 通过 `_cooldown_ok()` 做去重冷却（红线 300 秒 / 预警 900 秒），避免刷屏。

### 建议

1. **监控维度扩充（P1）**
   在「盈亏 + 日内波动」之外，加入：集中度（单票仓位占比）、连续亏损交易日计数、最大回撤（从峰值回落）、
   挂单是否超时未成交等维度，让监控从「单点阈值」升级为「组合健康度画像」。

2. **分批计划的量化输出（P1）**
   当前建议以「是否分批 / 是否离场」为主。建议让风控 Agent 在触发时**直接给出可执行的分批方案**：
   - 卖出：按「首笔 1/3 落袋 + 剩余分批」拆分，标注每批数量与目标价位。
   - 买入：按「先建底仓 1/3 + 回踩补仓」拆分，结合 ATR 给出参考区间。
   方案可作为 `suggested_prompt` 交给交易执行 Agent 落地为可编辑的委托单，而非停留在文案层。

3. **建议的确认与执行闭环（P1）**
   把监控建议的「按此建议执行」与通用 `pending_action` 机制打通：
   用户点击后进入 `ActionConfirmPanel`（复用交易/自选确认），经 `SafetyGate` 最小权限提权后真正下单，
   而不是仅发一条 prompt 重新走一轮对话。

4. **回测式复盘（P2，教育价值）**
   记录每条监控建议触发的时点、当时价格、后续 N 日走势，形成「建议是否及时」的复盘样本，
   用于评估纪律的有效性，也向用户展示「纪律交易 vs 情绪交易」的差异——这本身就是投资者教育的一部分。

5. **多账户 / 多会话路由（P2）**
   当前监控面向 `user_id = "default"` 单用户。若扩展到多用户，需把 `_target_session()` 升级为按 `user_id` 路由，
   并隔离每个用户的持仓、会话与推送。

## 四、复杂买入 / 卖出策略的制定

### 现状

- 交易执行 Agent 融合「基本面 + 技术面 + 消息面」，并附 ATR 止损 / 止盈纪律（短线 1% / 1.5%，中长线按 ATR 倍数）。
- `quant_prediction.py` 做短 / 中长线目标价预测，短线偏差限制在 [0.15%, 0.9%]。
- `chief_strategist._detect_time_horizon` 识别短 / 中长线交易周期。
- 持仓监控补充了「分批买卖」的纪律触发。

### 建议

1. **策略模板化（P0）**
   把「分批买入 / 分批卖出 / 定投 / 网格 / 止盈止损」沉淀为**可配置的策略模板**（`strategy_templates` 表），
   每个模板含：触发条件、分批比例、仓位上限、止损止盈线、时间周期。
   用户选择模板后，风控与交易执行 Agent 统一按模板约束生成建议，避免每次都由 LLM 自由发挥导致的不一致。

2. **分层交易计划结构（P1）**
   将交易计划从「单一委托」升级为「计划 → 多个子订单」：
   - `plan_id` 关联多笔 `orders`，支持「首笔建仓 → 分批补仓 → 止损离场」的序列化执行。
   - 前端 `TradeConfirmPanel` 展示整个分批计划的概览，逐笔确认，而非只确认一笔。

3. **状态机驱动执行（P1）**
   用轻量状态机（`planned → partial_filled → holding → trimming → exited`）跟踪分批计划进度，
   风控监控在每次巡检时按当前状态推进下一步建议，形成「计划随市场演进」的动态策略，而不是一次性给出全部。

4. **与定时任务协同（P1）**
   复杂策略天然需要「定时盯盘」：把「开盘竞价评估」「盘中分批执行」「收盘复盘」绑定为定时任务模板，
   让策略在无人值守时也能按纪律推进（仍保留人工确认兜底）。

5. **回测与评估（P2）**
   引入轻量回测（基于已有 K 线缓存），对策略模板做历史区间验证，输出胜率 / 最大回撤 / 盈亏比，
   结果写入 `eval_results`，让「策略好不好」有数据支撑——同时强化「模拟教育」的严谨性。

## 五、工程化收尾建议（P2，按需）

- **容器化**：`Dockerfile` + `docker-compose.yml`（后端 + 前端 + SQLite 卷挂载），降低部署门槛。
- **数据库迁移**：引入 alembic 或轻量迁移脚本，替代手动 `schema.sql`，便于演进表结构。
- **API 版本化 / 分页**：`/api/v1` 前缀与列表接口分页，为多用户 / 多会话扩展做准备。
- **遗留清理**：`schema.sql` 中的 `pending_orders` 表已无代码调用，可在下一次迁移时评估删除或改造为「分批计划表」。

## 六、优先级总览

| 优先级 | 主题 | 关键动作 | 定位关联 |
|--------|------|---------|---------|
| P0 | 定时结果回写会话 | 复用 `push_system_message` + 持久化 | 闭环 / 示例 |
| P0 | 策略模板化 | `strategy_templates` + 模板驱动建议 | 纪律 / 教育 |
| P1 | 监控维度扩充 | 集中度 / 回撤 / 挂单超时 | 风控 |
| P1 | 分批计划量化输出 | 风控给出可执行分批方案 | 策略 |
| P1 | 建议确认执行闭环 | 打通 `pending_action` + `SafetyGate` | 人机协同 |
| P1 | Cron + 交易日历联动 | 调度更贴近真实节奏 | 示例 |
| P1 | 分层交易计划 | `plan_id` 关联多子订单 + 状态机 | 策略 |
| P2 | 回测复盘 / 容器化 / 迁移 / 分页 | 评估 + 部署收尾 | 工程化 |
